# 显著提分筛选：密集局部与成对交互

2026-10-09。用户明确只关注显著收益，停止继续扩展小幅尾序、固定权重融合和损失权重微调。当前官方第五版0.7185908013668432，所有新方法先用本地16GB GPU；不启动付费算力或上传新文件。

## 候选判断与门槛

本轮假设：第五版将第6层256个patch压成4×4的16节点，并用单次软匹配，可能丢失相似舰船的细部区分信息。提高到8×8的64节点，再加入两轮双向条件交互，是改变可用信息和函数形式的强候选；是否显著提升必须实测。

[TransMatcher论文](https://arxiv.org/abs/2105.14432)和[作者实现](https://github.com/ShengcaiLiao/TransMatcher)研究图像成对匹配，简化其decoder为对应相似度、max pooling和MLP，并指出普通cross-attention不自动解决匹配问题。本轮自主实现双向条件节点更新，再沿用已有局部匹配/关系读出，不复制其模型、权重或声称论文复现。人像论文的收益不能换算为光学/SAR舰船成绩。

先跑第五版选中的seed20261009两组各24轮：64节点旧判别器作为信息量对照；64节点两轮交互判别器作为主候选。保持冻结骨干/CLS头、原11候选训练池、CE与局部独立辅助CE权重0.5、AdamW及每2轮development最佳选择规则。若完整检索增量和40个固定条件集合模拟增量都低于0.03，则停止扩种子；如有任一项至少0.03，同时要求另一项及复用报告组相对原头的退步不超过0.005，再启动第二种子确认。门槛在分数取得前写入，不是官方预测。

上一轮双向CE和Sinkhorn不再扩大实验。SDF-Net/MOS等训练表征约束保留，但不把其另一数据集论文表格当大幅比赛收益的证据；后续优先评估从当前分类特征转向直接成对判别是否有明显信号。

## 实现与检验

新增track6/cross_pair_verifier.py：每轮根据光学/SAR可学习key的余弦产生双向软匹配，用对方value更新本图节点，经残差/归一化/FFN后再计算已有局部关系残差。没有逐patch真配准标签或船体分割假设，几何读出只作为特征。全局头冻结，输出层零初始化保持初始分数。

提取入口增加--grid 4|8|16，仍绑定原生检查点、划分和缓存CLS摘要；老默认保持4。训练入口增加--pair-model local|cross、--node-cache和--seeds，仍使用共同GPU锁、保存源码快照及模型重载检查。第五版架构文件不修改，公开生产模型/预测绑定不变。

6项配对CPU测试通过，覆盖交互确实依赖对方图像、双方向梯度/冻结全局、缓存复用与chunk/重载一致。64节点提取7,409张图的CLS全部精确重放，耗时69.86秒，GPU allocated约811MiB，无优化器更新或测试图像。

## 比赛瓶颈的组件诊断

新09头固定配对首位，改用其前50学习式尾序：条件分0.849652→0.852726，相对第五版同场景0.834800仅+0.017926，32增8降；完整图库0.852622略低。即使同时用新头替换配对与尾序，也不是大幅突破。20%/50%查询身份不重合的20场景各组仍为压力检查，不能代表真实测试身份关系。

真实配对带来的变化远大于单独桥接，支持优先提升跨模态查询配对的识别。上述标签只来自验证身份；桥接选择第一个同身份合法图，而不是最大化AP的oracle，原O2O也保持，因此不是严格的AP上界，更不是0.96的可提交方案。实际隐藏查询是否符合共同不同身份仍未证实。
