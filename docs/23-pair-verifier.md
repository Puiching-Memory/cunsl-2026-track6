# 冻结TransOSS的学习式配对判别器

2026-10-08，本地RTX 4060 Ti 16GB。官方最好仍为第四版0.6699152061；无租机、比赛预测或提交。匿名记录见[证据](evidence/2026-10-08-pair-verifier.json)。

结论：全局CLS配对头取得小幅本地收益，两种子确认组同向，但增量区间均包含零。联合匹配后的条件模拟收益更小，目前不足以作为大幅提分方案。局部结构交互尚未实现，本次结果不是所有学习式匹配方法的上限。

## 实现与协议

冻结原生TransOSS第53轮模型。提取正式审查后的5,926张训练图、2,827个身份，其中2,819个成对身份生成正对，单模态身份可提供负对。没有提取或打分测试图。

判别器拼接归一化光学/SAR CLS的逐坐标绝对差和乘积，经128/64维MLP输出余弦分数残差。205,313个参数，残差输出层从零初始化。不读取patch，不包含几何对应或概率校准。

每身份在两个方向各采样一次，候选为1正对、8个完整训练图库前32名中的异身份困难负对、2个随机异身份负对。11候选listwise交叉熵；AdamW，LR0.0003、weight decay 0.01，每批256组。

固定种子20261008/20261009，各24轮。原验证身份经哈希等分development/confirmation；development选各自epoch，confirmation不参与判别头训练或选择。完整原图库保持，只重排原余弦前50候选，O2O排名固定。报告两个种子，不因confirmation较高而选择第二个。

此前TransOSS骨干选择及研究已使用原验证集，confirmation只对本次判别头选择留出，不是项目级独立测试集。

| 种子20261009，选择21轮 | 0.574639 | 0.579198 | +0.011683 |

development基线0.548186，两头0.569358/0.568285。第一种子development更高、第二种子confirmation更高，保留这种不一致。完整验证增量+0.013681/+0.015869。

第一种子O2S首位修正38个、添错27个，S2O修正55个、添错45个；第二种子分别42/25和41/30。确认身份分组、固定图库10,000次配对bootstrap，增量95%条件区间[-0.010417,+0.022539]、[-0.003282,+0.027098]，均跨零。不包含此前调参和官方分布差异。

## 运行与核验

训练特征提取41.42秒、峰值allocated 756.21MiB；两个配对头训练与验证合计64.09秒、峰值allocated 234.91MiB，不含驱动/桌面占用。原TransOSS零优化器更新。

两头保存重载后完整分数矩阵逐元素一致；独立标量R1/AP复算一致，3项新单测覆盖同身份负例屏蔽、初始余弦起点、梯度和批量方向索引，Ruff通过。修正CPU研究脚本路径导入格式警告后复跑，原记录保留。特征提取脚本执行后经Ruff格式化，证据分别保存运行时和当前源码摘要。

实现位于`track6/pair_verifier.py`及`tools/{extract_pair_training_features,train_pair_verifier,study_pair_verifier}.py`，产物在Git忽略的`local/pair-verifier/`。

已有GPU依赖下运行，训练须由`tools/run_job.py --gpu-lock local/local-gpu/gpu.lock`包裹：

```text
python tools/extract_pair_training_features.py --output-dir local/pair-verifier/native-training
python tools/train_pair_verifier.py --output-dir local/pair-verifier/cls-v1
python tools/study_pair_verifier.py
```

输出目录首次为空；复跑新目录需同步调整研究脚本的固定缓存路径。

## 后续判断

训练采样命中率最终约98%，未见身份完整检索首位仍约47%–48%，提示泛化与信息瓶颈值得研究，但不是因果证明。后置CLS头无法恢复骨干压缩掉的局部信息。

进一步学习式匹配应读取中间层局部token，和本次CLS头及固定局部匹配对照。本次confirmation今后已成为可见研究数据，不能继续当作新实验的封存确认组。局部交互扩展本轮未执行。
