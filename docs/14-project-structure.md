# TransOSS 项目重构与研究主线

2026-10-07按用户要求将研究收敛到TransOSS，删除DINOv2/v3骨干、旧身份微调、冻结特征适配器及相关训练/预测入口、专用测试和运行配置。历史论文讨论、实测、配置和资源许可审查保留为文档，既有研究产物保留在Git外。

## 当前职责

模型层 track6/transoss.py只负责作者骨干构造、配对初始化加载、图像编码、BN neck和身份损失。vendor保留原作者文件及MIT许可，骨干摘要仍固定。

训练层 training.py负责成对身份采样、SGD、逐轮验证和选择；selection.py独立管理耐心和严格最佳。数据和评分不依赖模型实现，继续沿用已验证的data/audit/protocol/metrics模块。

推理层 inference.py只恢复完整模型和提取特征，没有训练分支；checkpoints.py核对架构、初始化摘要和数据/划分绑定；runtime.py负责随机状态、设备和统一图像批次。训练和推理入口均不再导入其他工具脚本。

CLI只解析参数并调用库模块；configs/transoss.toml实际参与执行。训练只生成验证结果，predict_transoss.py才可显式生成测试预测。模型无关的候选诊断、错配和观察册保留用于TransOSS研究。

## 兼容与验证边界

保留已提交第53轮检查点的字段、BN缓冲区、分类头、256输入及验证/测试分批方式。恢复不再依赖原预训练文件，输出复制检查点原字节；同时保留资源审查和初始化摘要绑定。独立评分新增完整reid.pt摘要核验。

原学习率、采样、增强、损失、早停和检索特征不因重构改变。CPU合成流程用于验证模块连接、梯度、模型选择、恢复、预测格式及独立评分，不是新的比赛成绩。实际GPU数值一致性需在下一次已授权训练/推理时检查，不为本次重构租机。

本机隔离PyTorch 2.6.0+CPU实测46项检查，43项通过，3项Linux共享GPU锁检查按平台跳过。合成流程实际训练两轮，保持检索分数相同时选中第0轮，并确认训练后BN缓冲区恢复为该最佳轮次；随后无优化器恢复、预测格式与独立评分均通过。现有已提交第53轮完整检查点按真实数据/划分绑定严格加载，原SHA-256 f7c8886d不变，光学和SAR两张合成输入输出有限的768维特征；这不替代完整GPU验证集评分。匿名核验见[重构证据](evidence/2026-10-07-project-refactor.json)。

历史文档中的旧命令、路径和DINO成绩用于解释已有研究，相关源码已删除，不再可执行。旧配置及资源清单转为[文档归档](archive/dino-settings.md)，旧工具说明保存在[历史页](archive/legacy-tools.md)。当前运行命令见[工具说明](../tools/README.md)。

## 后续研究

以当前官方0.5144077657作为基线，每个TransOSS改动先做同协议验证，再做独立划分确认。重点检查跨模态首位识别：已有前10命中约86%，首位约46%。先控制预算研究身份采样、多光学视图及CE/triplet设置，再检查形状/背景与图像增强；逐项改变变量，避免同时改架构、损失和训练量后无法归因。

验证集参与最佳轮次选择，需要明确选择偏差。物理尺度嵌入需要有效元数据，当前不启用。所有新预训练资源须单独审查公开日期和许可，测试身份不参与训练或候选标签推断。
